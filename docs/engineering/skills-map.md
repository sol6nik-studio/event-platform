# Project Skills map and responsibility matrix

This is the routing source of truth for project-local Skills. Automatic discovery stays enabled for every Skill.

| Skill | Owns | Activates for | Explicitly does not own |
| --- | --- | --- | --- |
| `arena-product-requirements` | scope, actors, flows, acceptance, metrics | product behavior or priority changes | implementation design and code review |
| `arena-tournament-domain` | tournament vocabulary, entities and state machines | format, eligibility, match/result/dispute rules | HTTP, persistence and UI mechanics |
| `arena-system-architecture` | boundaries, dependencies, qualities and ADRs | modules, infrastructure and integrations | endpoint details and migration SQL |
| `arena-backend-node` | API/worker implementation policy | NestJS, Fastify, application services, jobs, realtime | product scope and browser rendering |
| `arena-frontend-next` | Next.js rendering/data/UI state policy | routes, components and frontend data flow | visual token ownership and backend rules |
| `arena-api-contracts` | versioned OpenAPI and client compatibility | endpoints, schemas, pagination, webhooks | internal domain implementation |
| `arena-database` | PostgreSQL/Prisma data lifecycle | models, constraints, queries, migrations, backup | API shape and product retention decisions alone |
| `arena-auth-security` | ASVS controls, authorization, privacy and threat review | auth, PII, uploads, secrets or trust boundaries | general UX styling and operations scheduling |
| `arena-design-system` | tokens, components, content and WCAG behavior | visual or interaction work | product priority and server authorization |
| `arena-testing-quality` | test portfolio and release quality evidence | test changes, bug fixes and quality gates | production deploy mechanics |
| `arena-observability` | telemetry, SLI/SLO and alerts | new critical paths or operational signals | deployment execution and product analytics ownership |
| `arena-devops-release` | environments, CI/CD, deploy, rollback and DR | infrastructure/release workflows | application domain behavior |
| `arena-code-review` | risk-based review findings and merge recommendation | reviews, audits and pre-merge checks | authoring a feature unless explicitly requested |

## Required composition

- A feature starts with product acceptance. If it changes tournament behavior, domain rules are resolved before API or persistence design.
- Architecture owns module placement; API owns external representation; database owns durable representation. None substitutes for another.
- Backend and frontend Skills implement only after their owning product/domain/contract decisions exist.
- Security, testing and observability are mandatory for every externally reachable or critical mutation path. Design system is mandatory for user-visible UI.
- DevOps owns deployability and rollback; code review independently reports remaining risk.

## File plan

- `AGENTS.md`: global constitution and routing only.
- `.codex/skills/<name>/SKILL.md`: scoped decision workflow; `agents/openai.yaml`: discoverable UI metadata.
- `.codex/skills/<name>/references/*.md`: only the detailed source of truth owned by that Skill.
- `docs/engineering/technology-baseline.md`: exact versions and update control.
- `docs/engineering/requirements-traceability.md`: requirement-to-source/test/CI mapping.
- `docs/engineering/definition-of-done.md`: universal and risk-specific completion evidence.
- `docs/engineering/skills-audit.md`: validator and conflict audit report.
- `scripts/validate-skills.mjs`: deterministic repository validator invoked by `pnpm skills:validate`.

Existing application code and legacy top-level product/architecture documents are not regenerated by this system task. New work follows the constitution and owning Skill references; conflicts must be resolved explicitly rather than copied between sources.
